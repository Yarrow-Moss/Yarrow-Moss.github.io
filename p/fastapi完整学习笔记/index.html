一、FastAPI 是什么

FastAPI 是一个基于 Python 类型提示（Type Hints） 的现代 Web 框架，用于构建高性能 API。它在 2018 年由 Sebastián Ramírez 发布，如今已成为 Python 后端最主流的框架之一。

官方四大特性：

特性 说明
快 性能与 Go/Node.js 相当（基于 Starlette + Uvicorn 异步栈）
快编码 开发速度提升 200%~300%，代码量大幅减少
少 Bug 基于类型提示的自动校验，约减少 40% 人为错误
自带文档 自动生成 Swagger（/docs）与 ReDoc（/redoc）交互式 API 文档

1.1 与其他框架对比

对比项 FastAPI Flask Django
性能 高（异步原生） 中（同步 WSGI） 中
请求校验 类型提示自动校验 手动 手动
自动文档 ✅ 内置 Swagger/ReDoc ❌ 需第三方 ❌ 需第三方
异步支持 ✅ 原生 async/await 需扩展 3.1+ 逐步支持
依赖注入 ✅ 内置 Depends ❌ ✅ 类似机制
适合场景 高并发 API、微服务 轻量服务、快速原型 大型全栈、后台管理

# ---------- 1. 导入区：引入所有必需组件 ----------
from fastapi import FastAPI, Depends, HTTPException, BackgroundTasks, Header, APIRouter
from pydantic import BaseModel, Field
from typing import Optional, List
from fastapi.middleware.cors import CORSMiddleware
import uvicorn
import time

# ---------- 2. 配置层：管理环境变量与应用设置 ----------
class Settings(BaseModel):
    app_name: str = "Awesome API"
    admin_email: str = "admin@example.com"
settings = Settings()

# ---------- 3. 数据模型层(Pydantic)：定义请求/响应结构 ----------
class TaskCreate(BaseModel):
    title: str = Field(..., min_length=1, max_length=50, description="任务标题")
    description: Optional[str] = None
    priority: int = Field(1, ge=1, le=5, description="优先级1-5")

class TaskResponse(BaseModel):
    id: int
    title: str
    priority: int
    class Config:
        from_attributes = True  # 允许自动转换ORM/字典对象

# ---------- 4. 依赖注入层：提供数据库和认证逻辑 ----------
# 模拟内存数据库
fake_db = {}
task_id_counter = 1

async def get_db():
    # 真实项目里这里会 yield 一个 SQLAlchemy Session
    return fake_db

async def get_current_user(authorization: Optional[str] = Header(None)):
    if authorization != "Bearer secret-token":
        raise HTTPException(status_code=401, detail="无效的Token")
    return {"username": "test_user"}

# ---------- 5. 路由层(APIRouter)：模块化处理业务逻辑 ----------
task_router = APIRouter(prefix="/api/v1/tasks", tags=["任务管理"])

# 后台任务函数（异步执行，不阻塞响应）
def send_notification(username: str, title: str):
    time.sleep(2)  # 模拟发邮件耗时
    print(f"已向 {username} 发送关于 '{title}' 的通知")

@task_router.post("/", response_model=TaskResponse, status_code=201)
async def create_task(
    task_data: TaskCreate,
    background_tasks: BackgroundTasks,
    db: dict = Depends(get_db),
    current_user: dict = Depends(get_current_user)
):
    global task_id_counter
    # 1. 触发后台任务
    background_tasks.add_task(send_notification, current_user["username"], task_data.title)
    
    # 2. 存储数据
    new_task = task_data.model_dump()
    new_task["id"] = task_id_counter
    db[task_id_counter] = new_task
    task_id_counter += 1
    return new_task

@task_router.get("/{task_id}", response_model=TaskResponse)
async def get_task(task_id: int, db: dict = Depends(get_db)):
    task = db.get(task_id)
    if not task:
        raise HTTPException(status_code=404, detail=f"任务 {task_id} 未找到")
    return task

@task_router.get("/", response_model=List[TaskResponse])
async def list_tasks(db: dict = Depends(get_db)):
    return list(db.values())

# ---------- 6. 主应用实例 & 中间件 ----------
app = FastAPI(
    title=settings.app_name,
    description="一个完整的FastAPI示例程序",
    version="1.0.0"
)

# 添加跨域中间件（生产环境需锁死域名）
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# ---------- 7. 生命周期事件(启动/关闭钩子) ----------
@app.on_event("startup")
async def startup_event():
    print(f"应用 {settings.app_name} 正在启动...")
    # 这里通常初始化数据库连接池、Redis连接等

@app.on_event("shutdown")
async def shutdown_event():
    print("应用正在优雅关闭...")
    # 这里通常关闭连接池、保存缓存等

# ---------- 8. 根路由 & 注册子路由 ----------
@app.get("/")
async def root():
    return {"message": f"欢迎来到 {settings.app_name}"}

# 把前面定义的 task_router 挂载到 app 上
app.include_router(task_router)

# ---------- 9. 本地调试入口 ----------
if __name__ == "__main__":
    uvicorn.run("main:app", host="0.0.0.0", port=8000, reload=True)

3.1 导入区 —— 一切的起点

把所需组件按"用途分组"导入，保持清晰即可：

from fastapi import FastAPI, Depends, HTTPException, BackgroundTasks, Header, APIRouter

3.3 数据模型层（Pydantic）—— 请求/响应结构的"合同"

你问过的 Item 类就是这一层。 它定义了两份"合同"：

  • TaskCreate：请求长什么样 —— 客户端必须按此格式提交
  • TaskResponse：响应长什么样 —— 服务端保证按此格式返回
1
2
3

class TaskCreate(BaseModel):
    title: str = Field(..., min_length=1, max_length=50, description="任务标题")
    priority: int = Field(1, ge=1, le=5, description="优先级1-5")

Field(...) 的 . . . 表示必填；ge=1, le=5 表示范围限制 1~5。Pydantic 会自动完成：

  1. 类型转换：字符串 "3" 自动转成 int 3
  2. 校验：title 为空、priority 超出范围 → 自动返回 422 错误
  3. 序列化：model_dump() 转成字典，model_validate() 从字典/ORM 转回模型

⚠️ 注意：Pydantic v2 中 Config 嵌套类写法改为 model_config = ConfigDict(from_attributes=True)，dict() 改为 model_dump()。老教程的 orm_mode = True 已弃用。

3.4 依赖注入层 —— 把重复逻辑封装成"零件" 

1
2
3
4

async def get_current_user(authorization: Optional[str] = Header(None)):
    if authorization != "Bearer secret-token":
        raise HTTPException(status_code=401, detail="无效的Token")
    return {"username": "test_user"}

核心思想：把"提取 Token → 校验 → 返回用户"这段逻辑封装成零件。路由函数只需声明：

1

current_user: dict = Depends(get_current_user)

框架自动完成三件事：执行依赖 → 拿到返回值 → 注入到参数。

依赖注入解决了什么问题？

问题 不用 DI 的写法 用 DI 的写法
每个接口都要校验 Token 每个函数重复复制校验代码 声明 Depends(get_current_user)
数据库连接谁负责开关 每个函数手动管理 yield 依赖自动开关
测试时换假数据 改业务代码 覆盖依赖即可

进阶：yield 依赖（资源释放型，数据库场景必备）：

1
2
3
4
5
6

async def get_db():
    db = DatabaseSession()      # 创建连接
    try:
        yield db                # 函数执行期间持有
    finally:
        db.close()              # 请求结束自动关闭

3.5 路由层 —— “注册处理函数"的核心

这就是你提到的"注册处理函数"机制的实现：

1
2

@task_router.post("/", response_model=TaskResponse, status_code=201)
async def create_task(task_data: TaskCreate, ...):

装饰器 @task_router.post("/") 的本质：把一个函数注册进路由表，告诉框架"当收到 POST /api/v1/tasks/ 请求时，调用这个函数”。

值得注意的几个设计细节：

  • 为什么用 APIRouter 而不是 @app？ 模块化。任务管理、用户管理、订单管理各建一个 router，互相独立、互不干扰，最后统一挂载。
  • response_model=TaskResponse：声明响应走 Pydantic 序列化，文档自动生成，并保证返回结构一致（比如防泄露多余字段）。
  • status_code=201：创建成功应返回 201 Created。
  • task_id: int 路径参数：声明 int 后，访问 /api/v1/tasks/abc 会自动返回 422（类型错误），无需手动解析。
  • BackgroundTasks：send_notification 会在响应返回之后由 Starlette 在后台执行，用户请求瞬间完成，2 秒的模拟邮件耗时不会阻塞响应。

3.6 主应用 & 中间件 —— 整个程序的大总管 

1
2

app = FastAPI(title=..., description=..., version="1.0.0")
app.add_middleware(CORSMiddleware, ...)

app 是唯一的全局实例，它同时扮演多个角色：路由表容器、中间件堆栈入口、生命周期管理器。

中间件执行时机（请求进出顺序）：

1

客户端请求 → 中间件(预处理) → 路由分发 → 业务函数 → 响应 → 中间件(后处理) → 客户端

CORS 中间件解决的是浏览器跨域问题：前端 localhost:3000 调后端 localhost:8000 时，浏览器会先发 OPTIONS 预检请求，CORS 中间件负责放行并返回允许的头部。

⚠️ 生产环境务必把 allow_origins=["*"] 换成具体域名列表，并谨慎开启 allow_credentials=True（与通配符 * 不能同时使用）。

自定义中间件示例（记录每个请求耗时）：

import time

@app.middleware("http")
async def log_requests(request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    duration = time.perf_counter() - start
    print(f"{request.method} {request.url.path} 耗时 {duration:.3f}s")
    return response

3.8 分层关系总结表

层级 代码位置 作用与讲解
1. 导入区 顶部 import 基础。把所有需要的工具包拉进来。
2. 配置层 class Settings 集中管理可变配置（如数据库连接串、域名）。生产环境通常从 .env 文件读取，避免硬编码。
3. 数据模型层 TaskCreate, TaskResponse Item类就是这里。 定义"请求长什么样"和"响应长什么样"，负责自动校验与序列化。
4. 依赖注入层 get_db, get_current_user 把重复逻辑封装成"零件"。 路由函数只需 Depends(...) 即可直接拿到用户信息，完全解耦。
5. 路由层（业务逻辑） @task_router.post 等 “注册处理函数"核心。 APIRouter 把"任务管理"这组接口单独拆分，最后统一挂载。
6. 主应用实例 & 中间件 app = FastAPI(...) 大总管。 中间件在请求到达路由之前、响应返回客户端之前统一处理。
7. 生命周期事件 @app.on_event("startup") 服务启动/关闭时的"钩子”。 初始化连接池、加载模型等一次性操作。
8. 根路由 & 注册 app.include_router 把拆分出的子路由挂载回主应用。“注册"概念的最终合并动作。

3.9 一次请求的完整旅程 

  sequenceDiagram
    participant Client
    participant Middleware as 中间件(CORS等)
    participant Route as 路由分发
    participant Dep as 依赖注入
    participant Handler as 路由处理函数
    participant Background as 后台任务

    Client->>Middleware: 发起请求
    Middleware->>Route: 预处理后转交
    Route->>Dep: 匹配到处理函数
    Dep->>Dep: 校验Token/准备DB
    Dep->>Handler: 注入依赖+参数
    Handler->>Handler: 业务逻辑
    Handler-->>Client: 返回响应(序列化)
    Handler-->>Background: 响应后执行通知

5.3 后台任务与异步

BackgroundTasks 适合轻量级任务（发邮件、写日志）。重任务（视频转码、爬虫）应交给 Celery 等消息队列，因为后台任务仍然共享工作进程，大量耗时任务会拖垮性能。

另外注意：普通函数与 async 函数混用是安全的——FastAPI 会把同步函数放进线程池执行，不会阻塞事件循环。

5.4 认证方式对比

方式 适合场景 说明
Header 手动校验 学习、内部工具 本文示例，最简单
OAuth2 Password Flow 自建系统登录 OAuth2PasswordBearer + JWT，带完整登录文档
API Key 第三方开发者 Header/Query 传 key
JWT 无状态认证 前后端分离 token 内含用户信息，服务端不存 session

六、常见坑与避坑指南

  1. Config 写法过时：Pydantic v2 用 model_config = ConfigDict(...)；orm_mode → from_attributes
  2. CORS 全放开：allow_origins=["*"] + allow_credentials=True 组合浏览器会报错，且生产有安全风险
  3. on_event 已弃用：新项目直接用 lifespan 上下文管理器
  4. 同步阻塞函数：耗时操作（如 time.sleep）在 async 函数里会阻塞整个事件循环，要么用同步函数（自动进线程池），要么用 asyncio 异步版本
  5. 全局变量计数：生产环境 task_id_counter 这种内存状态多进程下会错乱（Uvicorn 多 worker 时），请用数据库自增 ID
  6. Optional[str] = None 默认值：Pydantic v2 中可省略 Optional，直接 str | None = None（Python 3.10+）

七、一个值得注意的细节

你可能注意到了，这里的路由用的是 @task_router 而不是 @app。这在大型项目中是强推写法：

  • 如果有"用户模块”、“订单模块”，每个模块各自有独立的 APIRouter，最后统一挂载到 app
  • 它完全符合你的理解：本质上还是在"注册处理函数"，只是从直接注册到 app，变成了先注册到 router，再由 app 把整个 router 批量合并。这是你后续构建大型项目的必经之路
